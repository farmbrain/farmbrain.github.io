# FarmBrain project website

Jekyll site for the NSF FarmBrain project, served at <https://farmbrain.github.io>.

All content is data-driven. You should not need to edit any HTML:

| Page         | Edit this file              |
|--------------|-----------------------------|
| Overview     | `_data/project.yml`         |
| Personnel    | `_data/people.yml`          |
| Publications | `_bibliography/papers.bib`  |
| Nav bar      | `_data/navigation.yml`      |

The Overview diagrams are inline SVGs generated by `scripts/gen_diagrams.py`.
Edit the script, then run `python3 scripts/gen_diagrams.py`. Don't edit
`_includes/diagrams/*.svg` by hand.

Images go in `assets/img/` (people photos in `assets/img/people/`). Paper PDFs go in
`assets/papers/` and slides in `assets/slides/`.

## Adding a publication

Append a BibTeX entry to `_bibliography/papers.bib`. Entries are grouped by year,
newest first. Beyond standard fields, the site understands `abbr`, `pdf`, `slides`,
`arxiv`, `code`, `video`, `website`, and `abstract`:

Do not put an `@` inside `%` comments in the `.bib` file. The BibTeX parser treats it
as the start of an entry.

## Deploying

Pushing to `main` builds and deploys the site through GitHub Actions
(`.github/workflows/pages.yml`). In the repo settings, set **Pages → Source** to
**GitHub Actions**. The site uses `jekyll-scholar`, which the classic GitHub Pages
builder does not support.

## Local preview

Requires Ruby ≥ 3.0:

```sh
bundle install
bundle exec jekyll serve      # http://localhost:4000
```

Or with Docker (no local Ruby needed):

```sh
docker compose up             # http://localhost:4000, live reload
```

The first run installs gems into a cached volume; later runs start quickly.
